# Porting ADC_TM7 support to Kernel 6.18

**Date:** 20 August 2026
**Branch:** `marble-6.18-full-port`
**Status:** A preliminary patch integrated statically and fully built; untested on device.

## Goal and scope

This round addresses the existing `qcom,adc-tm7` node in marble's Device Tree, without modifying DTS or DTBO. Rather than importing the complete Xiaomi 5.10 package, the patch extends the existing 6.18 `qcom-spmi-adc-tm5` driver, because the Gen2 path therein matches the programming model required by ADC_TM7: selecting SID, ADC channel, BTM channel, thresholds, and IRQ.

This approach keeps the Kconfig and Makefile usage on the existing path `CONFIG_QCOM_SPMI_ADC_TM5`, which is enabled in the diagnostic AOSP configuration. The patch does not add any vendor API, QPNP headers, or a Xiaomi-specific client layer.

| Item | Decision implemented |
|---|---|
| DT matching | Add `qcom,adc-tm7` to the Gen2 driver's `of_match` table. |
| thermal identity | Preserve the full default channel identifier from `reg` for use in `thermal-sensors`. |
| hardware programming | Use the child index as the physical BTM channel, and extract SID from the high bytes of the default ADC channel. |
| IIO channels | Read `io-channels` from the parent node and match each channel to an ADC number and SID before use. |
| inherited DT properties | Support Xiaomi nodes' `qcom,hw-settle-time`, while leaving other standard Gen2 properties unchanged. |
| DTS/Kconfig/Makefile | No changes; the existing node and build configuration are sufficient for static linking. |

## Why the Xiaomi driver wasn't ported as-is

The Xiaomi 5.10 driver depends on vendor interfaces not present in 6.18, including QPNP revid and an ADC_TM client interface. Introducing them now would add a broad vendor layer without evidence it is necessary for the standard thermal path. In contrast, the Gen2 driver in 6.18 exposes the same standard IIO and thermal OF interfaces and already contains the SID and default channel logic required for ADC_TM7.

The patch also rejects IIO matches that are incompatible with the default DT channel. This protection prevents a spurious probe from succeeding with a thermal channel bound to the wrong ADC input or SID due to an unexpected `io-channels` ordering.

## Acceptance conditions before on-device trial

ADC_TM7 support must not be considered complete until all of the following conditions are met on a target ROM with recovery images installed:

1. A successful probe for `qcom,adc-tm7` with no repeated `-EPROBE_DEFER` or IIO/SID matching failures.
2. Registration of `cpu_therm`, `flash_therm`, `quiet_therm` regions and the remaining reference zones with the expected sensor IDs.
3. Reasonable temperature readings from each channel, then exercising one trip configured per critical channel.
4. No reset or IRQ storm or suspend/resume regression.
5. Capture UART and `pstore` and three stable boot cycles before expanding scope to SPSS or any other vendor component.
