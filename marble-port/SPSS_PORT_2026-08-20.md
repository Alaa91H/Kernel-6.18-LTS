# Initial SPSS Port to Kernel 6.18

**Date:** 2026-08-20
**Branch:** `marble-6.18-full-port`
**Scope:** Prepare support for SPSS and its associated GLINK for build and static analysis only. This round does not include enabling the device node, firmware package, a flashable image, or on-device testing.

## Implementation summary

An initial standalone support for Secure Processor Subsystem (SPSS) was added instead of importing the full Xiaomi vendor layer. The driver targets the `qcom,cape-spss-pas` node already present in the migrated Device Tree, and keeps it inactive as long as `status = "disabled"` remains. The driver loads the reference firmware name `spss.mdt` via PAS ID `14` and uses the `remoteproc` path and `QCOM_SCM` and `QCOM_MDT_LOADER` present in 6.18.

| Component | Result |
|---|---|
| `drivers/remoteproc/qcom_spss.c` | New SPSS driver adapted to 6.18; manages PAS and the `memory-region`, SCSR, clocks/regulators and SSR. |
| `drivers/rpmsg/qcom_glink_spss.c` | GLINK transport customized for SPSS using SMEM descriptor `478` and mailbox and IRQs specified in `glink-edge`. |
| `include/linux/rpmsg/qcom_glink_spss.h` | Small internal interface between remoteproc and transport; does not add a userspace ABI. |
| `drivers/*/Kconfig` and `Makefile` | Two new optional symbols: `QCOM_SPSS` and `RPMSG_QCOM_GLINK_SPSS`. No defconfig changes. |
| Device Tree and SPCOM | Not modified. SPSS node is not enabled and there is no vendor userspace layer in this patch. |

## Porting decisions

The port relies on `qcom_mdt_load()` and `qcom_scm_pas_auth_and_reset()` from the implementation available in 6.18 rather than literally carrying PAS interfaces from 5.10. The GLINK channel is registered as an `rproc_subdev` and is created only during the remoteproc lifecycle; it reads `qcom,remote-pid` and `reg-names` and mailbox and IRQ from the existing `glink-edge` child. The port makes no change to channel numbers, SID, or `reg` for the purpose of silencing DTC warnings.

SPCOM support is kept out of scope. This path constitutes an independent vendor ABI and requires a separate inventory of userspace interfaces and vendor packages before porting. Self-recovery of the remoteproc is also left disabled, because the effect of restarting SPSS on the target ROM cannot be demonstrated without a device and a recovery plan.

## Acceptance requirements before enabling SPSS

Do not remove `status = "disabled"` from the SPSS node until a single target ROM and the original firmware copies containing `spss.mdt` and matching segments are prepared, and KMI and vendor modules compatibility is verified. Recovery must be proven on original images first, then use UART and `pstore` during the first probe. The experiment should begin by enabling SPSS only without SPCOM, then verify PAS signals, SCSR logs, GLINK/SMEM and the mailbox. Enabling SPSS must not be combined with ADC_TM7 changes or DTBO or unrelated vendor definitions in a single build.

> A successful build only proves static interface integration. It does not prove firmware authentication, correctness of SMEM address, mailbox direction, or SPSS lifecycle integrity on-device.
